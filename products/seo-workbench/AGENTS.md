# SEO Workbench maintainer instructions

Root AGENTS.md and public repository policy apply. This directory is a separately
versioned MIT executable product, not an installable skill. Read README.md,
docs/architecture.md, docs/security.md and the repository task before substantial edits.

Use the canonical SEO Expert skill for source/evidence interpretation, Development
Planning for consequential design decisions, Agentic Codebase for instruction/layout
changes, Web UI Craft for interface work and Professional Code Comments for meaningful
API/implementation explanations. These triggers are maintainer guidance; no duplicate
skill install is needed. The implementation request already authorizes local work.

- Preserve immutable observations and analysis versions. Missing evidence is not pass.
- Keep strict configuration validation and operator-only network permissions.
- Rendering uses fresh sandboxed Chromium sessions and the shared resource broker.
  Never disable Chromium sandboxing or use a personal browser profile. Do not add
  container launchers or image settings. Local routing is not a network firewall.
- Never add arbitrary shell/SQL/browser execution or policy-changing MCP tools.
- Keep UI and reports free of captured HTML execution and automatic external requests.
- Keep databases, website captures, reports, browser artifacts and provider inputs
  outside the checkout. Only original synthetic source fixtures belong here.
- Run `npm run check`, `npm run build`, `npm test`, and the optional browser suite
  when affecting rendering/UI. Run root library/privacy checks before handoff.
- Test changed rules with defects, valid counterexamples and missing evidence.
  Keep data/rules.json linked to sources and canonical skill guidance through checks.
- Publication and paid/private integrations require their own authorization.
  Do not describe this preview as the entire requested finished product.

## User-facing language

Write interface copy, explanations, errors, reports and command help in plain,
readable English. Use complete sentences for explanations: say what happened,
what it means and what the reader can do next. Explain necessary SEO terms on
first use. Avoid implementation jargon, unexplained abbreviations, slogans and
compressed fragments. Keep button labels short and specific. Lead human reports
with findings and practical steps; place raw records in a labelled technical
section. Preserve machine-readable field names, stable identifiers and original
captured website text. Never simplify away uncertainty, safety limits or evidence.

Every heading, caption and explanation must help the reader understand a result,
make a decision or use a control. Remove slogans, motivational taglines and generic
prefaces rather than replacing them with new slogans. Explain a shared limitation
once near the relevant section; do not repeat it on every card or disclosure.
Keep uncertainty where it affects interpretation. Never claim an “AI-free” audit
proves authorship; judge wording by its clarity, accuracy and usefulness.
