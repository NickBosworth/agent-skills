## Execution order and preserved constraints

Complete scope and risky security/platform/data prerequisites first. Then close feature
and workflow requirements, repeat current scale and human acceptance, freeze one
candidate, obtain independent clearance and request publication only for that reviewed
candidate. Independent work can continue while a platform or account is unavailable.

Keep observations and historical analyses immutable. New schemas need transactional,
repeatable migrations and synthetic old/new compatibility and recovery checks. Never
rewrite a historical review to invent its basis. A code rollback does not reverse a
data migration; demonstrate recovery separately. Preserve the independent skills and
product packaging, anonymous Git metadata and mandatory public-repository policy.

Each increment must identify affected callers, exports, tests and documents. Use a
focused defect/counterexample/failure test, then relevant combined gates. Record exact
environments and intentional skips. Broader independent review and live service checks
remain separate from unit tests and source inspection.

Stop the affected release gate for unresolved material security findings, data-loss
risk, inaccurate SEO outcomes, permission bypass, private-data exposure or unverified
advertised platform support. Do not weaken acceptance, add broad scan exclusions or
silently defer original requirements to clear a gate. Scope deferral needs an explicit
decision. Raw private reproduction data stays outside the repository.

## First operational increment

`backup NEW_DIRECTORY` creates an exclusively selected private folder using SQLite's
backup API, then runs integrity and foreign-key checks. Existing folders are refused,
failed new backups are removed and source data is not replaced. Queued/running or owned
jobs must stop first. Restore by selecting the verified backup folder as the data
directory; jobs do not restart automatically. Do not copy just the main live WAL file.

`retention PROJECT --before TIMESTAMP` previews stopped audit histories older than the
cutoff. Apply only with its exact selection token and `--confirm-delete`. The selection
is checked and deleted in one write transaction. Changed selections are refused;
paused/active jobs and other projects survive, as do project-level provider imports.
Selected audit review decisions are removed with their history. No scheduler is
installed and deletion cannot erase backups, snapshots or copied reports.

Native Windows privacy and same-user filesystem replacement races are not certified
by POSIX folder modes or these preflight checks. Backups contain full private evidence,
must remain outside source and must be protected like the original data directory.

An interrupted process can leave an incomplete backup folder. Its completion marker
blocks normal Store recovery before database modification. Use the original data and
remove only the incomplete backup folder before retrying; do not remove the marker to
pretend verification finished. Normal failed backups are removed automatically.

## Worker ownership increment — 2026-10-12

Schema 5 adds ownership metadata and a separate private SQLite lifetime lock.
A dead modern worker can be recovered even when its old process ID is reused;
competing workers and premature resume are refused while the lock is held. Recovery
preserves other paused/cancelled decisions. Claim/recovery metadata is transactional;
locks are released on failure, completion cleanup, Store closure or process death.
Lock files and side files use the same ordinary-file/link checks as private storage.
Do not delete or replace the lock file while any worker could be running.

Stop all old workers and clients before upgrading. A possibly live legacy owner
refuses migration without committing it. Concurrent old/new executables are not
supported. Preserve a verified stopped backup for rollback: older code refuses
schema 5, and reverting source does not downgrade private data. Ambiguous legacy
process-ID reuse remains conservative; native Windows and physical fault acceptance
are still unverified. Backup validation now checks that the actual copied snapshot
contains no queued, active or owned job, closing the initial-preflight race.
