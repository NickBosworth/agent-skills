# Planning and execution

A directional plan records selected decisions, actual or clearly proposed paths,
ordered tasks, dependency boundaries, acceptance criteria, preserved rules, safe
verification, documentation, rollout/recovery and stop conditions. Reuse the project's
plan/task authority rather than creating a competing backlog.

Readiness means material design questions and prerequisites are resolved; it does
not mean approval. Name the plan revision and obtain applicable implementation
approval. For a plan-only request, deliver the plan without asking to execute again.
Approval supplied earlier remains valid within its scope; do not repeat it.

On resumption inspect the current revision, dirty files and completed evidence.
Distinguish planned, implemented and verified tasks. Reopen only the decisions
invalidated by new evidence. Preserve unrelated changes and useful prior work.

During execution follow the accepted sequence and checkpoints; complete authorized
work rather than stopping at a proposal. A new rule conflict, data risk or scope
change pauses the affected action while independent work continues. Never weaken
acceptance tests or fabricate a passing check. Close with observable results and an
accurate suggested commit message only after real implementation and verification.
