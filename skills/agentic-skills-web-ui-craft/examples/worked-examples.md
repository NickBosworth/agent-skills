# Synthetic worked examples

A fictional dashboard shows zero when its API fails. The repair introduces an
explicit unavailable state with retry and leaves genuine zero values unchanged.
Verification forces a failure and a valid zero response; no fabricated API success.

A fictional checkout animates confirmation before the server rejects payment.
The repair keeps pending state until authority confirms success, preserves valid
input after failure and restores focus to actionable feedback. Tests use a synthetic
payment service, never a real charge.

An approved dense operations table is called generic because it lacks whitespace.
The audit checks comparison tasks, headers, keyboard access and narrow-screen handling.
If density supports the users, preserve it; fix only observed barriers. These are
illustrations, not claims that a model or real user study executed them.
