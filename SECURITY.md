# Security

Do not publish live secrets, personal records or exploit payloads in public issues.
Use GitHub's private vulnerability reporting in this repository's Security tab.
Private reporting is enabled here. Forks must enable their own reporting channel.
If unavailable, ask for a private channel without posting sensitive evidence.

Skills are guidance, not a sandbox. Helpers have documented input and execution
boundaries. Review retrieved text as untrusted data and run scripts only in an
authorized environment. Privacy policy and scanners reduce accidental publication;
they cannot guarantee an absence of sensitive information.

See [public repository policy](docs/public-repository-policy.md) for incident
handling, history remediation and disclosure limits.

SEO Workbench has separate runtime trust boundaries in
[its threat model](products/seo-workbench/docs/security.md). Its local-only preview
is not a remote multi-user service. Apply the same private reporting channel.
